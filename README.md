# 제출OK (JeChulOK)

무료 파일 제출 준비 도구: https://jechulok.vercel.app/

## Agent Skill + local MCP v2.6.0 — AI가 로컬에서 제출 파일을 준비하도록

**[JeChulOK Submission Skill](.agents/skills/jechulok-submission/SKILL.md)**을 제공해요. Python 기반의 독립형 로컬 CLI로 JPG 사진 규격 검사·변환과 PDF 페이지 추출을 수행하고, 출력 파일의 실제 형식·용량·픽셀·페이지 수를 다시 확인합니다. 사용자 파일을 서버로 업로드하지 않으며, 기존 파일을 덮어쓰지 않습니다.

### v2.6: 피드백 개선 우선순위와 버전별 기술통계 비교

v2.5에서 사용자가 직접 남긴 **로컬 범주형 피드백**을 분석하는
별도 `feedback_insights_v26.py` 도구를 추가했어.

- `prioritize --directory ...`: 불편 유형의 **응답 빈도** 순위를 확인
- `compare --baseline-directory ... --current-directory ...`:
  두 폴더의 응답 비율 차이를 비교
- 각 집단에서 10건 이상이 필요하고, 소수 응답이 노출될 우려가
  있으면 세부 분석을 보류해.
- 파일 경로·개인정보·공고 원문·실제 사용자 기록은 출력하지 않으며,
  자동 저장이나 인터넷 전송도 없어.
- 독립적인 **20개 합성 평가 조건**과 단위 테스트를 추가했어.

**주의:** 자발적 피드백 빈도는 영향도나 사용자 전체의 만족도를
측정하지 않아. 두 폴더의 비교도 사용자 중복이나 버전 귀속을
확인할 수 없으므로 실제 개선 인과관계를 증명하지 못해.

### v2.5: 개인정보 없이 선택적으로 피드백 남기기

문제가 생겼을 때 피드백을 직접 남길 수 있는 **로컬 도구**를 추가했어.
자동 추적이나 온라인 전송은 하지 않으며, 사용자가 **단계·문제 유형·
영향 정도** 중 미리 정의된 답만 선택할 수 있어.

- `feedback_v25.py preview`: 저장하지 않고 기록될 범주를 미리 확인
- `feedback_v25.py save --output-dir ...`: 지정한 로컬 폴더에만 기록
- `feedback_v25.py summary --directory ...`: 선택한 폴더의 응답을 집계
- 기록에 이름·공고 원문·문서 경로·자유로운 의견·타임스탬프 등을 넣지 않아.
- 응답 수가 5개 미만이거나 작은 범주가 있으면 세부 집계를 숨겨.
- 실제 사용자를 대신하는 합성 응답 **30개 + 집계 검사 1개**를
  자동 검증하고 GitHub CI 결과에 안전성 평가 JSON을 남겨.

**실제 이용자 피드백이 수집되거나 분석됐다는 의미는 아니야.**
실제 사용자의 의견을 받기 위해서는 별도 동의와 자발적인 참여가 필요해.

### v2.4: 실제 첫 사용 흐름을 더 쉽게 안내

기존 `assist_submission` 호출 결과에 **경로를 표시하지 않는
사용자 경험 요약(`experience`)**을 추가했습니다.

- 다섯 단계 중 현재 위치와 **다음에 사람이 직접 해야 할 행동**을 표시합니다.
- 누락된 제출 서류의 **개수·항목 ID·예상 파일 형식**을 한 번에 제공합니다.
- 공고 오류와 준비 계획에서 막힌 조건 수를 별도로 표시합니다.
- 승인 없이 파일을 만들지 않으며, 진행률은 **단계 위치**일 뿐
  실제 파일 준비율이나 접수 완료율이 아닙니다.
- 개인 파일 경로·공고 원문을 이 새 요약에 다시 노출하지 않습니다.

서로 다른 합성 공고 6건의 4가지 상태를 조합한 **24개 자동 사용성
회귀 테스트**를 추가했습니다. 질문 절감률 비교는 가상의 파일별
질문 방식에 대한 계산이며 **실제 사용자 인터뷰·실험 결과가 아닙니다**.
공개 GitHub CI에서 통과 결과 JSON을 받을 수 있습니다.

### v2.3: 설치·오류 복구 전 과정 자동 검증

신뢰할 수 있는 ZIP과 새 설치 폴더를 확인하는 **읽기 전용
`recovery-plan` 명령**을 추가했습니다. 원래 설치를 보존하고,
사용자가 별도로 승인해야 하는 복구 절차만 안내합니다.

- 정상 설치 → 이전 설치 손상 → 손상 탐지 → 새 ZIP 검증 →
  새 폴더 복원 → MCP 재연결 → 클라이언트 설정 확인
- 임시 합성 데이터로 **14개 복구 시나리오**를 자동 실행합니다.
- 비정상 ZIP·기존 파일과 충돌하는 설치 경로·파일 해시 변조를
  거부하고, 기존 사용자 자료와 앱 설정 보존 여부를 검사합니다.
- 추출된 MCP 서버가 실제로 20개 도구에 응답하는지 확인합니다.
- GitHub Actions에 복구 평가 결과 JSON과 v2.3 배포 ZIP을 생성합니다.

**실제 이용자 14명이 테스트한 것이 아니라, 통제된 합성 시나리오
14건**이라는 점을 구분해야 합니다. 새 설치의 독립된 가상환경
설치, 사용자 앱 등록 및 수동 복구 절차는 여전히 따로 진행해야 합니다.

### v2.2: 사용자 친화적 설치·복구 안내

새 `guide` 명령으로 설치 상태를 **단계별 한국어/영어 설명**으로
확인할 수 있어. 사용자가 무엇을 고쳐야 할지 먼저 안내하지만
자동 설치나 파일 권한 변경은 하지 않아.

- `setup_mcp.py guide --allowed-dir YOUR_FOLDER`: 읽기 전용 한국어 안내
- `--language en`: 영어 설명, `--format json`: 프로그램에서 활용할 수 있는 결과
- `--client codex|cursor|claude-desktop`: 해당 클라이언트의 수동 설정 단계 표시
- `--probe`: 사용자 요청 시에만 **로컬 MCP 연결을 실제로 검사**
- 배포 파일 무결성 오류가 있으면 작업을 중지하고 안전한 새 설치를 권장.
  **손상된 현재 설치 프로그램을 실행하도록 안내하지 않음**
- 색상에 의존하지 않는 번호·설명 중심의 터미널 안내로 접근성 개선

기존 MCP 도구 **20개**와 파일 생성 승인·로컬 처리 정책을 유지했어.
공식 ZIP은 v2.2.0으로 갱신되며, 실제 외부 베타 사용자 검증이나
독립 보안감사가 완료된 것으로 의미하지 않아.

### v2.0: 배포 ZIP · 무결성 검사 · 안전한 나란히 설치

Python Agent Skill/MCP를 **실제로 내려받아 설치할 수 있는 ZIP 패키지**로
묶는 배포 도구를 추가했습니다. 기존 **20개 MCP 도구와 승인 규칙**은 그대로입니다.

- ZIP 내부에 소스 파일별 SHA-256 목록을 포함하고, 전체 ZIP의 SHA-256도 별도로 제공합니다.
- GitHub Actions에서 **패키지 생성 → 해시 검증 → 압축 해제 → 실제 MCP 연결**을 테스트합니다.
- 기존 설치는 덮어쓰지 않고 **새 폴더에 버전별로 설치**합니다.
- `setup_mcp.py upgrade`는 기본적으로 읽기 전용 미리보기이며, `--execute`가 있어야 새 파일을 만듭니다.
- 기존 가상환경 및 Codex·Cursor·Claude Desktop 설정은 변경하지 않습니다.
- `v2.0.0` 태그를 **별도로 생성하면**, 전체 테스트를 통과한 뒤 ZIP과 체크섬을 GitHub Release에 등록하도록 배포 워크플로를 구성했습니다.

**현재 GitHub Actions 아티팩트는 30일 보관하는 배포 후보 ZIP**입니다.
태그 기반 공식 GitHub Release 게시 여부는 별개이며, 태그가 생성되기 전에는
게시됐다고 볼 수 없습니다. 체크섬은 서명을 대신하지 않고, 외부 보안감사도
수행했다고 주장하지 않습니다. 설치 시 필요한 외부 Python 패키지는
초기 설치 중 인터넷이 필요할 수 있습니다.

### v1.9: 실제 공고로 평가할 수 있는 독립 검수 체계

v1.8의 합성 평가를 실제로 확장할 수 있도록 **로컬 실측 평가 엔진**을 추가했습니다.
사용 권한을 확보하고 개인정보를 제거한 공고를 별도로 준비한 다음,
**서로 다른 2명의 검수자가 독립적으로 작성한 정답 라벨**을 비교합니다.
의견이 다르면 제3자의 판정이 필요하고, 판정 전 사례는 정확도에서 제외합니다.

- **조건 누락률·잘못된 규격률:** 파일 유형·용량·픽셀·페이지 조건을 항목별로 비교
- **모호한 공고 차단률:** 사용자 확인이 필요한 사례를 안전하게 막았는지 평가
- **과도한 차단률:** 정상 공고를 불필요하게 거부했는지 평가
- **검수 일치율:** 두 사람의 독립적인 정답 라벨이 얼마나 일치했는지 확인

평가 실행 방법: 스킬 폴더에서 `python scripts/evaluate_real_v19.py private-evaluation/notices.notice-eval-private.jsonl --strict`.
입력 자료는 **로컬에만 보관**하고, 결과도 원문이나 식별자를 출력하지 않는 집계 JSON입니다.
권한·비식별화 점검이 없거나 대표적인 개인정보 패턴이 보이면 평가를 거부합니다.

**아직 실제 공고 데이터는 제공되거나 평가되지 않았으므로, 실제 정확도 수치는 없습니다.**
공개 GitHub CI는 합성 예제만 이용합니다.
사용법 및 데이터 스키마는 **[REAL_EVALUATION.md](.agents/skills/jechulok-submission/REAL_EVALUATION.md)**에서 확인할 수 있습니다.
기존 **20개 로컬 MCP 도구**와 웹사이트는 변경하지 않았습니다.

### v1.8: 합성 공고 100건 품질·안전성 자동 평가

새 평가 도구를 통해 **서로 다른 합성 공고 100건**을 아래 네 범주로
검증합니다. 실사용자 공고나 개인정보를 활용하지 않습니다.

- **모호한 조건 25건:** 공통 조건·중복 규격·지원 불가능한 조건을 무리하게 해석하지 않고 차단하는지
- **원본 추천 안내 25건:** 사용자가 폴더를 지정했을 때만 후보를 제시하고 자동 선택하지 않는지
- **승인 안전성 25건:** 승인 부족, 잘못된 계획 검증값, 출력 경로 변경, 미승인 자르기를 거부하는지

이 결과는 **합성 테스트의 통과율**입니다. 실제 공고 해석 정확도,

### v1.7: 필요한 질문은 줄이고 오류 안내는 정확하게

`assist_submission`에 대화형 서류 선택과 오류 설명을 보강했습니다.

- 원본 파일이 여러 개 부족하면 **한 번의 질문으로 모든 누락 항목**을

  로컬 폴더의 파일명·확장자를 검사해 항목별 후보를 최대 3개씩

### v1.3: 실제 작업 진행 조회 · 취소 · 안전한 롤백

기존 일괄 작업의 이중 승인 기능을 유지하면서 다음 MCP 도구 3개를 추가했습니다.

확인한 후 재실행해야 합니다. 취소한 작업은 자동 재시작되지 않으며,

### v0.3 한국어 제출 조건 해석

새 MCP 도구 `parse_submission_rules`는 ‘JPG 300×400px 500KB 이하’ 같은 문장을 기술 조건으로 분리하고 모호한 요구를 `needs_review`로 표시합니다. `prepare_from_requirements`는 명확한 JPG 조건이나 사용자가 페이지 범위를 지정한 PDF에 대해서만 새 파일을 만들고 결과를 다시 읽어 검사합니다. 기존 네 도구도 그대로 유지됩니다.

CLI도 같은 파서를 사용합니다: `python scripts/jechulok.py parse-rules --text 'JPG 300×400px 500KB 이하'`

JPG 또는 PNG 같은 선택형 조건, cm/mm, 픽셀 단위가 없는 숫자, `500KB 미만`, 흰색 배경, 얼굴 비율, 전자서명 등은 자동 제출 적합성으로 판단하지 않습니다. PDF는 사용자에게 어떤 페이지를 보존할지 별도로 확인합니다. 단위는 기존 CLI와 동일한 1024기준 KiB/MiB입니다. 상세 내용은 MCP.md를 참고하세요.

### v0.4: 긴 공고 · 다중 파일 제출 준비

- `analyze_submission_notice`: 명시적으로 이름이 붙은 사진·이력서·증명서 조건을 공고에서 항목별로 분리하고 근거 줄을 함께 반환합니다.
- `prepare_submission_batch`: 항목 ID와 실제 파일 경로를 **수동으로 매칭**한 뒤 전체 계획을 우선 미리보기로 보여줍니다.
- **실행 전 이중 승인**: `execute=true`, `confirm_execution=true`를 모두 지정해야 실제 결과 파일을 만듭니다.
- 모호한 규격이나 공통 미배정 조건이 있으면 실행하지 않습니다. PDF 페이지 삭제·추출 범위는 사용자가 직접 지정해야 합니다.
- 전체 사전 검사, 기존 파일 덮어쓰기 방지, 기술 조건 재검증, 중간 실패 시 생성 결과 되돌리기를 제공합니다.

```bash
python scripts/jechulok.py parse-notice --text $'- 증명사진: JPG 300×400px 500KB 이하\n- 이력서: PDF 5MB 이하, 최대 3페이지'
```

v0.4 당시 MCP는 **8개 도구**였습니다. 기존 `main` 웹서비스 배포에는 영향을 주지 않으며, 별도 로컬 CLI/MCP 서버입니다.


### v0.5: 로컬 파일 후보 추천 (읽기 전용)

새 MCP 도구 `suggest_submission_files(notice_text, directory_path)`는 사용자가
지정한 폴더의 파일명과 확장자만 읽고, 공고의 각 제출 항목에 대해 후보를
최대 5개씩 보여줍니다.

- **자동 매칭·자동 수정·자동 제출 없음**: 모든 후보는 사용자가 직접 확인한 후
  `prepare_submission_batch`에 명시적으로 입력해야 합니다.
- **비재귀 탐색**: 최대 250개 폴더 항목만 확인하며, 이 범위를 넘기면
  `truncated=true`를 반환합니다.
- **개인정보 보호**: 문서 본문을 열지 않고, 외부 서버에 전송하지 않습니다.
  심볼릭 링크 및 허용 폴더 바깥 경로를 제한합니다.
- **실행 승인 유지**: 미리보기 → 사용자가 파일·페이지 확인 →
  `execute=true`와 `confirm_execution=true` 승인 순서를 지킵니다.
- 이름만 비슷한 파일은 실제 올바른 서류라고 판정하지 않습니다.

공고 내용이 모호하면 이전과 같이 `needs_review`가 반환되어 일괄
실행하지 않습니다.


### v0.6: 제출용 파일명 추천 · 항목별 검증 현황

10번째 로컬 MCP 도구 `suggest_submission_output_paths`를 추가했습니다.
확인된 파일 매칭과 출력 폴더를 전달하면 `제출용_증명사진.jpg`처럼
읽기 전용으로 파일 이름을 제안합니다. 같은 이름이 있으면 번호를
붙이며 **파일은 생성하지도 예약하지도 않습니다.**

- 조건을 이미 만족하는 PDF는 새로운 복사본을 만들지 않도록 제안
- PDF가 조건을 벗어나면 페이지 삭제를 추측하지 않고 수동 선택 요청
- 실제 실행 전에는 기존 `prepare_submission_batch` 미리보기와 이중 승인 필요
- 작업 결과에는 `summary` 추가: 항목별 `technical_status`,
  기술 검증 수, 생성 파일 수, 미검증 수 및 검토가 필요한 항목
- `technically_verified`는 파일의 기계적 제약 검사만 통과했다는 뜻입니다.
  기관에 접수되었거나 서류 내용이 적합하다는 의미가 아닙니다.

### v0.7: 승인 검토 · 실패 수정 가이드 · 최종 제출 체크리스트

새 MCP 도구 `review_submission_plan`은 실제 파일을 만들지 않고
항목별 경로와 PDF 선택 페이지를 사전 검사합니다. 모호하거나 잘못된
매칭에 대해서는 원인별 수정 안내를 보여줍니다.
`awaiting_human_approval`은 **승인이 완료되었다는 뜻이 아닙니다.**
정확한 작업 계획을 사용자에게 보여준 뒤 별도로 실행 승인을 받아야 합니다.

새 MCP 도구 `verify_submission_package`는 최종 파일을 **다시 열어**
규격을 검사합니다. 사진 크기나 PDF 용량처럼 기계가 확인할 수 있는
조건만 검증하며 파일이 중간에 바뀌면 새로운 검사 결과를 반영합니다.

- 준비 전: 공고 원문, 입력·출력 경로, PDF 페이지, 사진 자르기 승인 점검
- 준비 후: 기술 검증 결과, 항목별 실패 원인과 수정 가이드 제공
- 접수 전: 사진 내용·PDF 서명·본문·접수 사이트의 완료 여부를 사용자가 확인
- `technical_pass`는 규격 검사 결과일 뿐 **실제 접수 완료가 아닙니다**
- 로컬 파일만 처리하며 자동 업로드·신청서 자동 제출은 지원하지 않습니다

기존 웹서비스는 그대로 유지됩니다.


### v0.8: AI의 다음 질문 안내 + 로컬 HTML 검증 보고서

  기본 호출은 **미리보기만** 하며 보고서를 만들지 않습니다.
